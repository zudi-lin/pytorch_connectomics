## Summary

Plan v1 correctly shows that `task.md`’s exact “dominance failure becomes NONE” explanation is inconsistent with `NucExtractor`. But it then mistakes the final CONFLICT state for the cause of the fusion. The evidence instead shows that nearly all cross-nucleus mask mass was already fused when CONFLICT was created. The proposed veto may shrink the blob’s untagged volume, but it cannot directly repair the measured nucleus-mask fusion.

## Findings

- [major] **Invariant D clause 2 cannot explain the measured tagged contamination.** Once a cluster is CONFLICT, the only permitted merge is with NONE, whose record has `total == 0`. Therefore every CONFLICT+NONE merge preserves the CONFLICT record’s `total`. The final `total=28,576,326`, which `/256` closely matches the observed 110–112K contaminated mask voxels, was already present when CONFLICT was created. Clause 2 may explain growth from that fused object to 291M total voxels, but not how those three nuclei became fused.

- [major] **The alternative reading is that CONFLICT is a post-hoc symptom.** Four `load_conflict_collisions` mean different child records already shared a segment ID before the composite load reconciled their nucleus identities. The supplied counter is not keyed by SID, and there is also one extraction-time `conflict_sv`, so it does not establish where this particular segment became CONFLICT. Moreover, zero “merge propagation violated” messages is expected: the loop repeats the same predicate on unchanged records after an earlier successful predicate check. It says nothing about which merge classes occurred.

- [major] **The refutation of `task.md` is only partial.** The code does refute its statement that missing the dominance ratio produces NONE—it produces CONFLICT unless below `min_tagged`. The subfloor count also rules out below-floor voxels themselves carrying 110K mask voxels. It does not rule out an untagged NONE shell acting as a bridge while separate child chunks attach local PROPER records, with the conflict appearing only when those records are loaded under the same SID. Thus the task’s precise mechanism is wrong, but plan v1 has not established clause 2 as the replacement cause.

- [major] **The treatment cannot directly satisfy V4’s primary criterion.** `load_nuc` and `reduce_nuc` create CONFLICT records without consulting `nuc_can_merge`; by then the records already have the same SID. Making the resulting cluster inert does not split that SID or remove its existing cross-nucleus mask mass. Any success would have to come from an unexplained indirect trajectory change in an earlier level. The proposed `conflict_absorbed` diagnostic is also misplaced: absorption occurs in the merge loop, and “tagged voxels absorbed” will always be zero in metadata because the absorbed operand is NONE. It should record the NONE operand’s `seg_size`, the conflict’s size at birth, hierarchy level, and SID.

- [major] **The proposed predicate code does not preserve flag-off behavior.** After the existing conflict/conflict guard, `if (conflict_a || conflict_b) return !nuc_strict_conflict();` allows CONFLICT+PROPER when the flag is off; if it replaces all current conflict branches, it also allows CONFLICT+CONFLICT. The flag-off equivalent must retain the other operand’s `NONE` check, for example `!strict && b.state == NONE` and its symmetric case. The plan also alternates between an unspecified global `nuc_strict_conflict()` and explicitly plumbing a parameter into call sites.

- [major] **The reducibility argument remains incomplete.** A static veto has a materially better local argument than a priority key: under strict mode, permitted in-loop joins cannot create CONFLICT, so pre-existing conflict clusters can potentially be treated as removed from the active graph. That closure argument—not merely commutativity and associativity—must be stated. Across hierarchy levels, however, `load_nuc`/`reduce_nuc` can create conflicts after child processing. The lossy extractor is partition-dependent: one child can emit PROPER-1, another PROPER-2, and their reduction is CONFLICT, while the combined raw counts can still be 70/30 and therefore monolithically PROPER-1. Strict mode then freezes only the distributed representation. A generic “mask spanning the boundary” fixture does not exercise this counterexample, so V3 does not establish chunk independence.

- [major] **`nonuc` is not the claimed discriminator, and its branches are not objectively defined.** A blob in `nonuc` does not prove the nucleus-constrained run completed the fusion before recognizing CONFLICT; strict treatment could still stop later growth. Conversely, a smaller `nonuc` result does not isolate clause 2 because removing all nucleus vetoes changes the entire mean-linkage trajectory. “Comparable” and “much smaller” have no size, overlap, or IoU thresholds. The direct discriminator is per-SID size/tagged mass at conflict birth versus volume subsequently absorbed through CONFLICT+NONE, followed by running strict treatment regardless. Raising `MIN_TAGGED` to 5000 also creates more NONE records, so `mint5000` is not inherently a safer alternative.

- [major] **V4 remains gameable and does not price the stated NERL risk.** A result with dominant share 0.9505 and five shared fragments of 0.0099 each passes criteria 1, 2, and 4 while retaining 4.95% shared contamination. Splitting the 291M blob into two 145M false objects passes the largest-segment ceiling with only one added record. Global segment count can also hide fragmentation behind unrelated false merges. No overlap/NERL or object-fragmentation metric is included. Criteria 2 and 4 additionally disagree between allowing clean dominance `>=0.999` and requiring exactly `1.000`; criterion 2 replaces “does not regress” with an unexplained `0.95` improvement requirement. Exact equality of contamination JSON in criterion 5 does not prove the full control segmentation was reproduced.

- [major] **Not all nine v0 findings are resolved.** F1–F5 are legitimately mooted by withdrawing ordering, and F8 is addressed. F6 remains because V3 lacks an adversarial load-created-CONFLICT case and explicit sidecar-state comparison. F7 is scoped away rather than tested; neither the inert V2 run nor one V3 insertion order tests treatment reproducibility. F9 remains through the subjective `nonuc` gate and gameable V4 criteria. Because the plan also abandons the task’s mandated ordering change, implementation requires explicit task-owner approval after a sound replacement diagnosis.
